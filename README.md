# 我的 NixOS 配置

> [!NOTE]
> 本仓库已停止维护，仅作为个人配置存档。部分配置与特定硬件绑定，请勿直接部署。

NixOS 是一个稳定且设计优雅的 Linux 发行版。经过数月的使用和磨合，在充分体验它的优势与代价之后，我最终还是决定向它告别。

对我而言，NixOS 带来的麻烦多于便利。如果需要投入成倍的时间，换来的却是自己并不迫切需要的可复现性，那么继续使用它便没有太大意义。

## 为什么尝试 NixOS

反复尝试不同的发行版既耗费精力，实际收益也未必很大。社区里经常可以看到对某款发行版的热情推荐，但这些推荐有时更关注它最亮眼的一面，而没有充分说明长期使用中的取舍。一句 “Bro, just give it a try. You'll love it.”，很容易让人忽略每个人的需求其实并不相同。

我正是在这类推荐的影响下开始尝试 NixOS。它先进而独特的设计、声明式配置、可复现性以及丰富的软件包都很吸引人。刚开始使用时，一切都很新鲜；遇到不适应的地方，我也认为只是自己尚未熟悉。然而随着使用时间增长，我逐渐发现，它的一些设计与我的实际需求并不契合，许多原本简单的工作也因此变得繁琐。

## 糖果与巴掌

### NixOS 的糖果

对我而言，NixOS 最有吸引力的是回滚机制和声明式配置。前者让我可以放心折腾系统，后者则让我只需在配置文件中声明一个服务，再执行 `nixos-rebuild switch`，便能完成安装与启用。

至于可复现性，它对我的个人主机价值有限；我的其他主机承担着不同的任务，也没有复制同一套环境的需求。

### NixOS 的巴掌

Nixpkgs 的软件包数量非常丰富，但部分软件的更新仍不够及时，即使使用 unstable 分支也偶有这种情况。软件包的查找和筛选不够方便，官方文档的使用体验也不尽如人意，网络教程的质量则参差不齐。这里推荐一下 [Lantian 的博客](https://lantian.pub/)。至于自行打包，即使有 AI 协助，对我来说依然比较麻烦。

更大的问题出现在软件开发中。Nix 对依赖和运行环境的处理方式与传统 Linux 发行版差异很大：非 Nix 构建的动态链接程序可能需要 `nix-ld`，带有原生依赖的 Python 项目也经常需要额外处理库路径。`pip` 和 `npm` 并非不可用，但临时安装依赖或使用全局环境时，往往需要配合虚拟环境、开发 Shell 或额外配置。这套工作方式并不符合我的习惯，而 `flake.nix`、devenv 和 Distrobox 等方案也都未能让我满意。

## 下一站

Debian 是我用过最舒适的发行版，Linux Mint 则在易用性与精致程度之间取得了很好的平衡。我不准备转向 Arch Linux，因为已经在折腾发行版上投入了太多时间。此外，Fedora 或许也是一个值得考虑的选择。
